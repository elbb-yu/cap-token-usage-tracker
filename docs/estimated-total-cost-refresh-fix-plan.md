# 刷新期间预估总费用显示修复计划书

## 1. 背景与目标

### 1.1 用户问题

仪表盘在自动刷新或点击“刷新”时，统计数据已经开始更新，但“预估总费用”卡片会短暂显示“不可用”。费用接口返回成功后，卡片又恢复为正确金额。该过程会造成费用数据确实丢失的误解，也使刷新期间的界面发生不必要的跳变。

### 1.2 修复目标

1. 刷新期间不再把已有的预估总费用清空为“不可用”。
2. 在新一轮费用查询完成前，继续显示上一轮成功取得的费用快照。
3. 新费用查询成功后，用新快照整体替换旧快照，确保最终金额、覆盖率、费用趋势和模型费用使用同一批数据。
4. 新费用查询失败时，继续保留上一轮成功快照，同时明确提示本轮费用刷新失败；不能把失败误显示为最新费用为零。
5. 日期范围、来源或模型筛选真正发生变化时，不能永久显示旧费用；新查询完成后必须使用新范围的数据。

## 2. 现状分析与根因

### 2.1 相关实现位置

| 文件 | 位置 | 作用 |
| --- | --- | --- |
| `dashboard.go` | `dateRangeQuery()` | 为滚动时间范围生成包含当前时间的 `start`/`end` 查询参数 |
| `dashboard.go` | `load()` | 先加载统计初始数据，再异步加载费用数据 |
| `dashboard.go` | `currentCosts`、`costQuery`、`costLoadError` | 保存费用快照、查询标识和错误状态 |
| `dashboard.go` | `render()` | 将统计数据和费用数据写入当前页面状态并触发渲染 |
| `dashboard.go` | `renderVisuals()` | 渲染 `totalCost`、费用覆盖率及费用相关图表 |
| `dashboard_test.go` | `TestDashboardRefreshRetainsMatchingCostSnapshot` | 已覆盖“查询完全相同”时保留费用快照的契约 |

### 2.2 已确认的触发链路

当前刷新流程如下：

1. `load()` 生成本轮 `query`，其中包含 `resolvedDateRange()` 计算的当前时间。
2. 统计初始接口返回后，执行：

   ```js
   render(initial, costQuery === query ? currentCosts : null)
   ```

3. 自动刷新时，`last_5_hours`、`last_7_days`、`last_30_days` 和 `current_month` 等滚动范围都会重新计算 `now`，所以本轮 `query` 的时间参数与上一轮 `costQuery` 不完全相同。
4. 查询不相同时，初始统计渲染会把费用参数强制变成 `null`。
5. `render()` 将 `currentCosts` 设为 `null`，随后 `renderVisuals()` 执行：

   ```js
   animateText('totalCost', costSummary ? money(costSummary.total_usd) : t('value.unavailable'))
   ```

6. 费用接口稍后成功返回时，页面才恢复金额。因此“不可用”是刷新过程中的前端状态覆盖，不是费用计算结果本身不可用。

现有测试只验证了查询字符串完全相同时的保留行为，未覆盖滚动时间范围导致查询字符串每次刷新变化的场景，所以该回归仍可能发生。

## 3. 修复方案

### 3.1 状态语义调整

保留 `currentCosts` 作为“最近一次成功取得、可用于显示的费用快照”，不要在统计初始数据到达时因查询参数变化而将它清空。增加一个轻量的费用刷新状态，推荐使用以下语义：

- `currentCosts`：最近一次成功费用响应，继续作为页面费用展示数据源。
- `costQuery`：`currentCosts` 对应的查询参数。
- `costLoading`：本轮费用请求是否正在进行。
- `costLoadError`：本轮费用请求失败信息；成功时清空。

费用请求开始时只更新 `costLoading`，不清空 `currentCosts`。统计数据先返回时继续渲染已有费用快照。费用请求成功时一次性更新 `currentCosts` 与 `costQuery`，再触发完整费用视图重绘。费用请求失败时只更新错误状态，不覆盖已有快照。

### 3.2 刷新期间的展示规则

1. **已有费用快照且费用正在刷新**：
   - `totalCost` 继续显示上一轮金额。
   - `costCoverage` 继续显示上一轮覆盖率，并追加本地化的“正在更新”状态；如现有状态文案不足，补充专用 locale key。
   - 费用趋势、模型费用和相关导出继续使用同一个上一轮快照，避免各组件分别出现空状态。
2. **已有费用快照但本轮费用请求失败**：
   - 卡片继续显示上一轮金额和覆盖率。
   - 错误区域显示费用请求失败信息，状态文案说明当前金额为上次成功结果，而不是本轮最新结果。
3. **首次加载且没有任何费用快照**：
   - 保留现在的“等待精确费用数据/不可用”逻辑，避免把尚未查询到的金额伪装成有效数据。
4. **切换日期范围或来源**：
   - 允许短暂保留上一轮快照作为刷新中的稳定展示，但必须通过刷新状态明确其不是本轮结果。
   - 新费用响应成功后，立即以新查询对应的快照替换旧快照。
5. **切换模型或隐藏模型**：
   - 继续由 `visibleCostSummary()` 基于当前筛选重新聚合 `currentCosts`，不新增第二套费用计算逻辑。

### 3.3 并发与过期响应

继续使用 `statsLoadSequence` 丢弃旧一轮统计请求，并把同一序号检查应用到费用请求的开始、成功和失败路径。只有当前序号的费用响应可以更新 `currentCosts`、`costQuery` 和 `costLoadError`。旧请求即使晚返回，也不能覆盖新一轮快照。

本次不把费用请求重新改回阻塞式 `Promise.all`，因为统计初始数据应继续先展示，费用数据也应独立失败；只调整费用快照生命周期和渲染状态。

## 4. 计划改动范围

### 4.1 `dashboard.go`

1. 调整费用加载状态变量，增加明确的 `costLoading` 状态或等价的请求序号状态。
2. 在 `load()` 的费用请求开始时保留 `currentCosts`，不再因为滚动时间范围的 `query` 变化而传入 `null` 覆盖已有快照。
3. 在费用成功路径中，确保 `currentCosts` 与 `costQuery` 同步更新，并只触发一次一致的费用视图重绘。
4. 在费用失败路径中，保留 `currentCosts`，只记录本轮错误并更新提示。
5. 修改 `render()`/`renderVisuals()` 的金额与覆盖率展示分支，使“没有快照”“正在刷新”“刷新失败但有旧快照”三种状态可区分。
6. 如需新增展示状态，补齐 `locales/en.json`、`locales/zh-CN.json`、`locales/zh-TW.json` 和 `locales/ru.json`，保持所有语言 key 完整。

### 4.2 `dashboard_test.go`

补充模板契约测试，覆盖以下前端行为：

- 滚动时间范围刷新时不能用 `render(initial,...null)` 清空已有费用快照。
- 费用加载开始、成功、失败三条路径都保留正确的快照语义。
- 当前刷新序号才能更新费用快照，过期费用响应必须被忽略。
- 首次加载没有费用快照时仍显示等待/不可用状态。
- 刷新期间金额保持旧值，新费用成功后才替换为新值。
- 费用错误提示不能把保留的旧金额误标为本轮最新金额。

如果现有字符串契约测试难以可靠表达状态机，应从内嵌脚本中抽取最小的纯 JavaScript 状态函数并使用 Node 执行测试；不在本次计划中引入前端框架或运行时依赖。

## 6. 风险与边界

### 6.1 旧数据短暂展示

刷新期间保留上一轮快照意味着滚动时间范围推进时，金额短暂滞后于当前统计范围。该滞后只存在于费用请求完成前，必须通过刷新状态标识；费用成功后必须替换。相比显示“不可用”，该方案更符合“数据仍可用但正在更新”的实际语义。

### 6.2 费用接口长期失败

不能无限期让旧金额看起来像最新金额。若失败状态持续，应在卡片详情和错误区域明确提示快照时间或“上次成功结果”，但不应将金额改为零或隐藏为不可用。是否增加快照时间展示属于本次实施时的 UI 细节，不能削弱错误可见性。

### 6.3 过滤维度一致性

费用快照可能对应上一轮来源筛选或日期范围，但模型隐藏/选择仍会在前端重新聚合。实施时必须让快照的查询范围与展示状态同时可识别，避免把上一轮金额与本轮统计标签拼成无标识的“最新总费用”。

## 7. 验收标准

1. 首次加载没有费用结果时，页面仍显示等待精确费用数据，不显示伪造金额。
2. 已有费用结果后，点击刷新或自动刷新，在费用接口返回前，“预估总费用”保持上一次金额，不出现“费用数据不可用/不可用”闪烁。
3. 对滚动时间范围刷新，费用接口成功后卡片金额、覆盖率、费用趋势、模型费用和请求费用全部切换到新范围结果。
4. 费用接口失败时，旧金额保留且错误可见；错误恢复后，新金额能正常替换旧金额。
5. 快速连续刷新时，旧响应不能覆盖较新请求的费用快照。
6. 日期范围和来源切换不破坏费用快照更新；模型选择和隐藏仍按当前快照正确聚合。
7. 普通模式和完整模式行为一致，不改变完整模式鉴权、价格管理、导出和后端费用计算接口。
8. 所有现有测试通过，并新增回归测试覆盖本计划第 4.2 节场景。
9. `go test ./...` 与 `go vet ./...` 均通过。
